# Bot lab

Headless training ground for Apple Royale bots.

- `sim.js` — runs headless rounds on the game core (`../core.js`, the same
  code the game runs), starting straight in "playing". Seeded and
  deterministic. Gameplay changes go in `core.js`, never here.
- `tools/core_check.js` — determinism check: a scripted round must give the
  same digest every run, in Node and in the browser.
- `arena.js` — evaluation CLI (`match`, `field`, `ladder`; see its header).
- `policies/*.js` — bots. `legacy.js` is the AI that once shipped in royale.js.
- `layouts/*.js` + `layout_arena.js` — alternative branch layouts and their
  referee (`rows.js` is the layout royale.js ships).

```
node bots/arena.js field blue_g1 --vs legacy --rounds 400
node bots/arena.js match blue_g2 red_g1 --rounds 400
node bots/arena.js ladder legacy blue_g1 blue_g2 red_g1 --rounds 1000
```

## Browser bundle

`bots.js` (repo root) is a plain copy of the champion policy that royale.js
drives at the difficulty levels in `TIERS.md`. After changing the champion,
regenerate it and check that it still plays identically:

```
{ echo '// GENERATED by copying bots/policies/blue_g4.js (the red/blue champion) --'
  echo '// do not edit here. Regenerate with the command in bots/README.md.'
  echo '// Defines window.APPLE_BOT = { create(rng, opts) } for royale.js.'
  echo '(function () {'
  echo '  const module = { exports: {} };'
  cat bots/policies/blue_g4.js
  echo '  window.APPLE_BOT = module.exports;'
  echo '})();'; } > bots.js
node bots/tools/browser_shape_check.js
```

(Point both at a new file name if a new champion replaces blue_g4.)

## Policy contract

```js
module.exports = {
  create(rng, opts) {          // rng(): seeded uniform [0,1); opts from "name:k=v"
    return { act(me, world) {  // called once per 1/60 s tick
      return { move: -1|0|1, button: true|false };  // button = held
    } };
  },
};
```

Same controls as a human: press (false→true) on a branch starts a charge;
release launches (held < 0.12 s = plain jump, full charge at 0.6 s ≈ 2.1×
height, rooted while crouched); press in the air = ground-pound (coyote
0.1 s after leaving a branch still jumps).
The top of the screen is a ceiling (apples bonk off it), and each bot only
starts acting a random 0–0.7 s after "GO!" (`C.BOT_START_JITTER`).

Readable state (read-only — the browser game exposes exactly these):

- `me` / each of `world.apples`: `index, alive, x, y, vx, vy, grounded,
  standingBranch, charging, charge, pounding, facing, squish`
- `world.branches[]`: `x, y, w, dead, solid` (center x, top surface at
  `y + C.BRANCH_HALF_THICK`)
- `world.killLine, world.scrollY, world.scrollSpeed, world.roundTime, world.C`

## Rules

1. Self-contained file: no `require`, no `Math.random` (use `rng`), no
   globals, no I/O. Must stay cheap (< ~0.2 ms per act).
2. Never write to `me`, `world`, apples or branches. Keep your own state in
   the closure.
3. Treat every other apple the same — never read `a.bot` or infer teammates.
   In the real game a bot faces one human and other bots.
4. Don't edit `sim.js` or `arena.js`. Extra tooling goes in new files.
